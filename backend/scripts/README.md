# Demo seed (opt-in)

Run from `backend/`:

```bash
python manage.py shell -c "exec(open('scripts/seed.py').read())"
```

The backend entrypoint does not run this script automatically. Set
`SEED_DEMO_DATA=true` only for a disposable development database, or run the
command manually as shown above. Before running it, set every
`SISPOA_DEMO_*_PASSWORD` variable listed in `.env.example` to an explicit
environment-specific value. The seed aborts if any required variable is absent
and never prints credential values.

For a safe cleanup of the existing demonstration/import data, use the explicit
two-step command:

```bash
python manage.py limpiar_datos_simulados --dry-run
python manage.py limpiar_datos_simulados --commit --include-ambiguous-test-data
```

The first command is read-only and emits counts plus primary keys. The second
command deletes only the allowlisted manifest in one transaction and preserves
the real administrator, roles, `CodigoNivel`, canonical SectorPAD `01`–`20`,
and canonical ODS `01`–`17`.

The seed is idempotent, uses deterministic demo keys, and never deletes
records outside those keys. Demo users require these environment variables:

| Login email | Required environment variable | Role focus |
|---|---|---|
| `admin@demo.sispoa.local` | `SISPOA_DEMO_ADMIN_PASSWORD` | Administration |
| `mae@demo.sispoa.local` | `SISPOA_DEMO_MAE_PASSWORD` | MAE |
| `planificador@demo.sispoa.local` | `SISPOA_DEMO_PLANNING_PASSWORD` | Planning |
| `presupuesto@demo.sispoa.local` | `SISPOA_DEMO_BUDGET_PASSWORD` | Budget |
| `tecnico@demo.sispoa.local` | `SISPOA_DEMO_TECHNICAL_PASSWORD` | Technical unit |
| `seguimiento@demo.sispoa.local` | `SISPOA_DEMO_MONITORING_PASSWORD` | Monitoring |
| `auditor@demo.sispoa.local` | `SISPOA_DEMO_AUDITOR_PASSWORD` | Audit |

The PGDESA, PDESA and PEI names generated by this script are explicitly
simulated.  ODS codes use the standard zero-padded identifiers `01`–`17`;
the remaining demo records are not official institutional data.
